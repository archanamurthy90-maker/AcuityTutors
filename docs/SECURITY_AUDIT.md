# Security Audit — Acuity Tutors (Assignment 5.4, Phase 4)

- **Date:** 2026-10-04
- **Scope:** the Express API (`server/src`), React client (`client/src`), Prisma schema and migrations, seed script, configuration and secret handling, git history, and the Gemini integration.
- **Method:** manual code review of every route, middleware, and client sink; searches for raw SQL, HTML injection sinks, secrets, and logging; git-history scan; automated tests (`server/tests/security.test.ts` and others); the live API checklist (`npm run test:api --workspace=server`); and a headless-browser CSP check of the production build.
- **Out of scope:** Cloud Run / Cloud SQL deployment (not configured), infrastructure, and third-party services beyond how this app calls them.

**Risk levels:** Critical (exploitable now, severe impact), High (realistic abuse of accounts or data), Medium (weakens a control or needs specific conditions), Low (hardening or minor exposure). **Status:** **Pass** (already secure; no change), **Fixed** (changed in this phase), **Accepted** (known residual risk with rationale), **Open** (needs an owner decision).

The checklist IDs SEC1–SEC15 in [TEST_CHECKLIST.md](TEST_CHECKLIST.md) are test cases; the SEC-NN IDs below are audit findings. [SECURITY_CHECKLIST.md](SECURITY_CHECKLIST.md) is the reusable control checklist.

### Abuse protection, headers, and browser policy

| ID | Risk | Vulnerability / area reviewed | Recommended fix | Actual fix | How to verify | Status |
|---|---|---|---|---|---|---|
| SEC-22 | High | No rate limiting. Passwords could be brute-forced without limit, accounts mass-created, and the AI endpoints called repeatedly to burn the Gemini quota (which is only 20 requests/day on the free tier). | Limit login, register, and AI endpoints, returning 429 with a friendly message. | `express-rate-limit` in `server/src/middleware/rateLimits.ts`. **Login:** 10 failed attempts per IP + email and 100 failed attempts per IP per 15 min (successful sign-ins don't count). **Register:** 20 accounts per IP per hour and 100 requests per IP per 15 min. **Practice questions:** 20 per student per 10 min. **Summaries:** 30 per tutor per 10 min. Each returns 429 with a friendly message plus `RateLimit`/`Retry-After` headers. Limits are sized for a tutoring center where many students share one network. With `NODE_ENV=production`, `trust proxy` is set to 1 so the limits see the client IP behind Cloud Run. | `security.test.ts` (4 rate-limit tests); live SEC2 (11th wrong login → 429, Ava still signs in). | Fixed |
| SEC-24 | Medium | No security headers: no CSP, `nosniff`, clickjacking protection, or HSTS. | `helmet` with a CSP that still lets the app and charts work. | `helmet` in `server/src/middleware/security.ts`. CSP: `default-src 'self'; script-src 'self'; style-src 'self'; img-src 'self' data:; font-src 'self'; connect-src 'self'; object-src 'none'; base-uri 'self'; form-action 'self'; frame-ancestors 'none'; script-src-attr 'none'`, with no `unsafe-inline`. Also `X-Frame-Options: DENY`, `nosniff`, HSTS, and Referrer-Policy. `upgrade-insecure-requests` is omitted so local plain-HTTP production checks work; HSTS covers HTTPS. In development, Vite serves the pages (so CSP doesn't apply to them) and Express adds headers to API responses. Recharts styles SVG through React style props (CSSOM), which `style-src` does not block. | `security.test.ts` header test; live SEC4; headless Edge against the production build signed in as Ava and the tutor: dashboards and Recharts charts render with **0 CSP violations** and 0 console errors (checklist SEC15). | Fixed |
| SEC-25 | Low | `/api/health` publicly showed whether the database was connected and whether Gemini was configured. | Return only a liveness status publicly. | With `NODE_ENV=production` it returns only `{"status":"ok"}`; local development keeps the detailed check. | `security.test.ts` health test; checklist SEC1. | Fixed |
| SEC-26 | Low | CORS was not configured. Browsers already blocked cross-origin reads (no `Access-Control-Allow-Origin`), but there was no explicit allowlist and no server-side check of cross-site writes. | Restrict CORS to the client origin. | `cors` with credentials for the `CLIENT_ORIGIN` allowlist (comma-separated; default `http://localhost:5173`) or same-host requests only. POST/PUT/PATCH/DELETE requests with a foreign `Origin` are rejected with 403 before reaching a route. | `security.test.ts` CORS test; live SEC8 (foreign origin: no ACAO header, POST 403; client origin allowed). | Fixed |
| SEC-27 | — | CSRF | SameSite cookies plus an origin check. | Already protected by the SameSite=Strict session cookie and JSON-only bodies; SEC-26 adds the origin check. | Checklist SEC8. | Pass |
| SEC-28 | — | Vulnerable dependencies | Keep `npm audit` clean. | None needed: `npm audit` reports 0 vulnerabilities after adding `helmet`, `cors`, and `express-rate-limit`. | `npm audit`; checklist SEC5. | Pass |
| SEC-31 | Low | Rate-limit counters live in each server instance's memory. With several Cloud Run instances, the effective limit is per instance, and counters reset on restart. | A shared store (for example Redis) if the app runs more than one instance. | Not changed: deployment is not configured and a single instance is expected for now. Documented in README. | — | Accepted |
